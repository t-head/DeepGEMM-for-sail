# Native W4A8 on PPU0015

The public NoPad, Masked and Fused APIs remain the C++ bindings exported by
`deep_gemm_cpp`. W4A8 uses the existing single extension, compiler, device
settings and launch framework. It requires packed E2M1 weights with group-32
UE8M0 scales, per-row E4M3 activations and BF16 outputs. Prepare operands with
`preprocess_weights_and_scales(PreprocessMode.W4A8_MXFP4_MMA, ...)` and apply
the returned inverse scale exactly once.

## Organization

| Layer | Source | Responsibility |
| --- | --- | --- |
| Public API | `csrc/apis/gemm.hpp` | Operand/metadata validation, device guard, explicit configs and inv_scale |
| Selection | `csrc/jit_kernels/heuristics/common_w4a8.hpp` | Measured shape domains, tile configs, shared memory and streamed chunk planning |
| JIT runtime | `csrc/jit_kernels/impls/m_grouped_w4a8_gemm.hpp` | Native, small-M and routed code generation, compiled handle readiness and launches |
| Streamed runtime | `csrc/jit_kernels/impls/w4a8_streamed_gemm.hpp` | Bounded workspaces, caller-owned stream/event state and decode/compute overlap |
| Device kernels | `deep_gemm/include/deep_gemm/impls/w4a8_{small_m,routed,streamed_*}.cuh` | Shared compute implementations and compile-time strategies |
| Scheduling | `deep_gemm/include/deep_gemm/scheduler/w4a8_*_scheduler.cuh` | Prefix schedules and per-call GPU routing records |

The historical E4M3 weight-decoder APIs and their packing/preprocessing helpers
have been removed. Optimized native W4A8 converts weights to E5M2 and computes
E4M3 x E5M2 with FP32 accumulation. There are no Python dispatch wrappers,
versioned backend modules, extra extension factories or private runtime namespaces.

## Selection and execution

Small-M, routed and streamed strategies preserve the accepted schedules. The
measured shape domains and tile sizes are centralized in the heuristics header;
device code derives N/K/groups/token count from templates and per-call arguments.
Other shapes use the existing native implementation. Explicit NoPad configs
and non-default inv_scale retain native execution and validation. Compile-only
mode retains the original native compiler/launch semantics.

Small-M uses a shared kernel with task-pair, shared-prefix or warp-prefix
scheduling. Routed kernels share the NoPad/Fused mainloop and use per-call GPU
metadata to select M160/M192 and bounded M loops. The bounded path permits at
most 1/1024 of the valid row count as extra padding; otherwise it uses exact
M16 tails. Fused requires the matching moe_align_block_size token layout;
NoPad receives activations already grouped by expert.

Streamed execution allocates and overwrites bounded partial FP8 weight tiles
on every call. One runtime selects fenced, fence-free or nonempty-expert decode.
Events order decode, compute and scratch reuse, then join the caller stream.
Only compiled code, shape readiness and resource identities are cached; input
values, decoded weights and outputs are never cached. Cold capture delegates
to native execution; ordinary warmup prepares optimized capture resources.

## Build and validation

Keep `opt/w4a8` as native PPU source based on upstream main `9f332d8`. Apply and
commit SDK preprocessing only in a separate build worktree, then compile there.
The existing cudafy CLI assumes older setup/compiler layouts, so the SDK 2.2
validation worktree uses the validated conversion plus its general SDK mapping
for new source/dependencies. Main-checkout source must not contain that commit.

`tests/test_w4a8.py` includes scale, configuration, small-M and routed regressions.
Run on PPU0015 with SDK 2.2 after building the isolated preprocessed worktree.

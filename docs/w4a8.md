# Native W4A8 on PPU0015

The public NoPad, Masked and Fused APIs use packed E2M1 weights with group-32
UE8M0 scales, per-row E4M3 activations, FP32 accumulation and BF16 output.
Prepare weights and scales with
`preprocess_weights_and_scales(PreprocessMode.W4A8_MXFP4_MMA, ...)`, and apply
the returned inverse scale exactly once to activation scales.

## Organization

| Layer | Source | Responsibility |
| --- | --- | --- |
| Public API | `csrc/apis/gemm.hpp` | Operand validation, device guard, configs and inverse scale |
| Selection | `csrc/jit_kernels/heuristics/common_w4a8.hpp` | Alignment, row reuse, scheduler capacity, resources and workspace plans |
| Native runtime | `csrc/jit_kernels/impls/m_grouped_w4a8_gemm.hpp` | One native JIT generator, compiled handles, metadata and profiling |
| Native kernel | `deep_gemm/include/deep_gemm/impls/w4fa8_gemm.cuh` | Shared copy, FP4 decode, pipeline and epilogue in `W4A8GEMM_MMA` |
| Schedulers | `deep_gemm/include/deep_gemm/scheduler/w4a8_*_scheduler.cuh` | Prefix scheduling and per-call routed records |
| Streamed runtime | `csrc/jit_kernels/impls/w4a8_streamed_gemm.hpp` | Partial decoded buffers, events, streams and capture readiness |

## Native strategies

The existing native configuration remains the default. Wider M tiles reuse
one decoded weight fragment across more output rows. Short-K configurations
retain their existing N expansion, resident activation tiles and split-K behavior.

The compact strategy uses a warp prefix for at most 64 experts and mean row
counts up to 64. M16 pairs tasks, M32 shares prefix storage, and M64 retains
the warp prefix. Compact K32 fragments reduce live register state. Selection
also requires aligned N/K, sufficient K work, and shared-memory/thread capacity.
It does not depend on model dimensions or an exact device name/CU count.

The routed strategy amortizes a device metadata pass over larger expert sets
with moderate rows per expert. M160/M192 candidates reuse decoded weights;
M16 tail counts limit unnecessary MMA work. The metadata pass compares actual
expert row counts and constructs fresh work records on every call. Both paths
use the same native kernel, with scheduler adapters and bounded compile-time
fragment strategies. Resource calculations stay in the heuristics layer; the
runtime initializes dynamic shared memory before checking actual occupancy.
Compiled candidates exceeding the local-storage budget retain native execution;
the runtime caches that resource decision without caching input values.

For Fused, work records preserve the expert token offsets padded for the
original public config returned by `moe_align_block_size`. Internal M tiles do
not reinterpret that layout. Non-default configs and unknown token layouts
retain native execution. NoPad starts with activations already grouped by expert.
Masked and non-unit `inv_scale` retain their native behavior.

## Streamed decoding

Streamed decoding is a separate NoPad strategy for sufficiently large weight
reuse. Eligibility uses dimension alignment, conservative rows per expert,
workspace size, and estimated chunk/wave overhead. Per-call device row counts
prune empty experts. The bounded plan decodes at most half the experts at once,
using two partial E5M2 weight buffers, each bounded by 384 MiB. Input values,
routing values and decoded weights are never cached across invocations.

Events order decoding, computation and buffer reuse, then join the caller
stream. Ordinary warmup prepares modules, stream/event resources and readiness
for the actual caller and shape. Capture without those resources returns to the
warmed native path before allocating a streamed buffer or loading a decoder.
Compile-only mode preserves the existing native compiler/launch behavior.

All successful native strategies preserve the operation parameters and HGTX
range controlled by `PPU_LIB_SHOW_PARAMS` and `PPU_LIB_PERF_INSTRUMENT`. Routed
instrumentation includes metadata construction. Configured CU counts are used
in launch planning.

## Validation and measurement

Use the SDK environment and build procedure in the repository README. Keep any
SDK compatibility conversion in a separate worktree.

`tests/test_w4a8.py` covers grouped modes, scales, explicit configs, empty and
uneven experts, shapes outside the initial tuning workloads, reduced configured
CU counts, and Fused metadata layouts. Streamed regressions cover ordinary and
new-stream execution, warmed Graph replay after activation/weight/scale updates,
and capture following compile-only warmup.

`tests/bench_w4a8.py` measures representative complete APIs using two output
addresses, 12 warmups, 15 rounds and 20 calls per round. Run the same driver
against each built revision using `PYTHONPATH`. Its optional profiler traces
separate main GEMM, metadata and decoding kernels; these durations use the
profiler's own timeline and can overlap. Host enqueue time is reported separately.
